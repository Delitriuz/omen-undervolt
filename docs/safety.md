# 安全边界与设备校验

## 设备校验

代码里没有机型和厂商白名单，判断完全来自固件：程序向 `hpqBIntM` 发 `0x35` 能力查询，返回数据索引 `2` 的 bit 0 置位即认为 BIOS 支持处理器降压。这个约定与 OmenHwCtl、OmenMon 的记录一致（`0x01` 表示支持，实机观察到 `0x03`）。

做不到时会明确报错而不是静默失败：非 HP 机器通常没有 `hpqBIntM`，报「找不到 HP BIOS WMI 接口」；接口存在但 BIOS 不支持时，报「BIOS 未报告处理器降压能力」。两种情况都会禁用写入。

## 写入前置条件

写入需同时满足：

1. 进程运行在管理员账户权限下。
2. 能连上 `hpqBIntM` 并成功发出 `0x35` 能力查询。
3. 能力数据长度至少为 3，且索引 `2` 的 bit 0 置位。
4. `0x36` 当前偏移读取成功并通过协议头校验。
5. 用户在二次确认对话框中明确选择继续。

任一固件调用返回非零错误码、WMI 接口缺失或响应无效时，当前读取／设置流程会报错并停止。

## WMI 调用格式

`src/HpBiosWmi.cs` 连接 `\\.\root\wmi`，从 `hpqBIntM` 调用 `hpqBIOSInt128`。输入含有：

- Command：`0x20008`
- Sign：ASCII 字节 `SECU`
- CommandType：能力查询 `0x35`、读取 `0x36`、设置 `0x37`
- 数据通过 `hpqBData` 传递

偏移读取请求长度为 4 字节，处理器标识放在第二个字节并设为 `3`。设置请求长度为 128 字节，数据布局如下：

| 字节 | 含义 |
|---|---|
| 0–1 | 处理器标识 `00 03` |
| 2 | `1` 表示零／非负偏移；`0` 表示负偏移 |
| 3–4 | 偏移幅度，大端序整数，单位 mV |
| 5–127 | 零填充 |

UI 输入是非负幅度；非零幅度作为负偏移写入。例如 `130` 编码后为 `00 03 00 00 82`，即 `-130 mV`。零值使用正／零符号并将幅度置零。

读取数据至少需要 9 字节，且处理器标识须为 `00 03`；否则解码拒绝该响应。界面幅度固定上限为 200 mV，编码器也会再次限制该范围。

## 不包含的保护

当前实现没有对用户输入做稳定性预测或自动回滚，也不验证电压偏移的运行效果。恢复 `0 mV` 是一次新的 BIOS 写入请求，仍需确认并可能要求重启。请把 BIOS 接受请求视为待重启状态，并在重启后重新读取。

本工具只使用 HP BIOS WMI 接口，不通过 UEFI 变量接口写固件；针对固件变量的独立分析不能推导出直接写变量是安全的。
